DataSentinel · incident management flow

Which notebook runs when, what it writes, and who uses the result · notebooks 30, 31, 32, 70–73, 79
1ONE-TIME SETUP (run once, before the first DAG run)
70incident_setuponce
Creates the rule tables: incident_routing (dataset → team, owner, escalation), priority_policy (critical → P1 / 60 min, high → P2 / 4 h…), runbooks (first steps per pillar), and the empty incident_ops, incident_events, alerts.
31dq_summaryonce
Creates quality views: v_dq_latest, v_pass_rate_by_dataset, v_pass_rate_after_fix. Views recompute on every read, so they never need a re-run.
73incident_viewsonce
Creates v_incident_board: every incident with priority, owner, age, minutes to acknowledge / resolve and SLA state (ON_TRACK, BREACHED, RESOLVED_IN_SLA, RESOLVED_LATE).
2EVERY DAG RUN (Airflow, every 30 min)
20quality_gatetask gate
rule failures, pass rate below SLO, breaker
30observability_monitorsmonitors
5 pillars: freshness, volume, distribution…
60recontask recon
R1–R10 cross-system checks
🔔 Incident opened / closed
sync_incidents() in 11_dq_lib · key dataset|check|scope · a failing check → OPEN · the check passes again → RESOLVED (no manual close)
71incident_managetask incidents · runs even if a step before failed
Reads the new and closed incidents and the rules from 70. Safe to re-run: nothing is assigned, alerted or closed twice.
① Assignpriority from severity, team + owner from routing, due time, runbook
② AlertP1 / P2 → one Slack digest per run; without a webhook it is logged
③ EscalateP1 / P2 not acknowledged in time → escalation_to (level 1, 2…)
④ Resolverecord RESOLVED for incidents the pipeline closed, notify who was alerted
3MONITORING TABLES (schema data_sentinel.monitoring)
dq_resultsone line per check per run (20 · 21 · 22 · 30 · 60)
incidentsOPEN / RESOLVED, key, severity
incident_opspriority, owner, due_at, ack, level
incident_eventstimeline OPENED → RESOLVED
alertsevery message sent or logged
4WHO USES THE RESULT
📊 Views from 31 + 73 → dashboards
Power BI: Data Quality page (pass rate per dataset, after fix) and Incidents page (board, SLA).
Review app: Alerts page (open incidents, KPIs, alert log).
